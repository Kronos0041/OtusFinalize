# ClothesShop

Дипломный проект: iOS-приложение для просмотра каталога одежды и аксессуаров. Пользователь сможет находить товары по категориям, изучать карточки, сохранять понравившееся и собирать корзину. Проект написан на Swift с интерфейсом SwiftUI. Минимальная версия — iOS 15.

## Функциональность и статус

| Функция | Сейчас | План для диплома |
| --- | --- | --- |
| Регистрация и вход | Firebase Authentication; после регистрации отправляется письмо на русском, доступ открывается после подтверждения email; ошибки и выход из аккаунта доступны в приложении | — |
| Каталог | Вкладка «Главная», данные из Firestore (`categories`, `products`), категории и поиск по названию и описанию при вводе. Состояния «нет сети», «пусто», «ошибка»; автоповтор при появлении сети; обновление свайпом (iOS 16+ в сетке, iOS 15+ на карточке) | — |
| Карточка товара | Фото, описание, цена, выбор размера и добавление в корзину. Для товара с размерами перед добавлением необходимо выбрать размер | — |
| Избранное | Можно поставить лайк; состояние хранится в памяти и синхронно отображается в разных разделах | Добавить отдельный список избранного и сохранение состояния между запусками |
| Корзина | Отдельная вкладка с бейджем количества: позиции с размерами, изменение количества, удаление свайпом, итог и демо-оформление. Сохраняется в `users/{uid}/cart` в Firestore и синхронизируется с аккаунтом; названия и цены берутся из актуального каталога, а максимальное количество — из `settings/store` | Без реальной оплаты и отправки заказа |
| Профиль | Email берётся из Firebase Authentication; доступны обновление данных аккаунта, смена email и пароля, выход | — |
| Уведомления | Загружаются из Firestore; прочитанным уведомление становится по нажатию, на колокольчике — число непрочитанных; есть состояния «нет сети», «пусто» и «ошибка», обновление свайпом | — |

Покупка и платёжная интеграция в объём диплома не входят. Оформление корзины, если потребуется для показа, будет демонстрационным и не создаст реальный заказ. Если проект перерастёт в стартап, к этим функциям можно будет вернуться 🙂

## Архитектура

Используется **MVVM**: SwiftUI `View` отображают интерфейс, модели описывают товары и данные пользователя, `ObservableObject` ViewModel хранит состояние экрана и обрабатывает действия. Сейчас в проекте есть `AuthVM`, `MainGrideVM`, `CartVM`, `NotificationsVM` и `MainViewModel`. `AuthenticationService` работает с Firebase Authentication, `FirestoreService` читает Firestore и записывает пользовательскую корзину. Оба сервиса находятся в `Services/Firebase`; имена коллекций вынесены в `FirestoreCollection`.

Экраны, которые грузят данные, работают через `ViewMode` (`loading` / `content` / `empty` / `noInternet` / `error`) и общий `ViewModeView` с заглушками. Доступность сети отслеживает `NetworkMonitor`.

`ViewModeView` является базовой оболочкой области данных для новых экранов. ViewModel определяет состояние, а экран передаёт контент, текст и иконку пустой заглушки, при необходимости действие повтора. Заголовок, навигация и постоянные действия остаются снаружи оболочки. Каталог, избранное, корзина, уведомления и профиль используют её для загрузки. При входе чтения `categories`, `products`, `settings/store` и `users/{uid}/cart` запускаются параллельно и объединяются в один стартовый результат для вкладок.

```swift
ViewModeView(viewModel.viewMode, retry: viewModel.reload) { data in
    ScreenContent(data: data)
}
```

Тексты интерфейса локализуются через `ClothesShop/Resources/en.lproj/Localizable.strings` и `ru.lproj/Localizable.strings`. SwiftGen генерирует типизированные строки со смысловыми ключами, например `SwiftGen.Profile.title`, и функции с подстановками, например `SwiftGen.Auth.Verification.instructions(email)`. Язык выбирается по настройкам приложения в iOS; письма Firebase используют тот же язык. Названия и описания товаров, категорий и уведомлений приходят из Firestore и отображаются как данные.

Конфигурация генерации находится в `swiftgen.yml`. После добавления ключа в оба файла выполните `swiftgen config run` (установка: `brew install swiftgen`). Xcode также запускает генерацию перед компиляцией при изменении английского файла или конфигурации. `ClothesShop/Resources/Generated/SwiftGen.swift` хранится в репозитории, поэтому проект можно собрать без установленного SwiftGen; редактировать этот файл вручную не нужно. Для проверки языков используйте Scheme → Run → Options → App Language: Russian / English.

Цвета и картинки лежат в `Assets.xcassets`, шрифты — в папке `Font` и регистрируются в `Info.plist`. Переход на VIPER с сохранением ViewModel описан в `REFACTORING.md`, раздел 10.

В ходе дипломной работы планируется выделить протоколы для источников данных и передавать их во ViewModel. Это позволит переключать реальные Firebase-сервисы и локальные моки, а также тестировать логику экранов без сети. Планируемая схема: `View → ViewModel → Repository → Firebase / Mock`.

## Технологии и библиотеки

- **SwiftUI** — интерфейс приложения; `ObservableObject` и `@Published` — обновление состояния экранов.
- **FirebaseCore** — инициализация Firebase.
- **FirebaseAuth** — регистрация, вход и состояние авторизации.
- **FirebaseFirestore** — каталог, уведомления и пользовательская корзина.
- **Swift Package Manager** — управление зависимостями. Используемые продукты подключены из официального пакета Firebase Apple SDK. FirebaseUI в коде не используется.

Фото опубликованы в Firebase Hosting по пути `https://test-6d334.web.app/products/<product-id>.png`. В URL добавлена версия содержимого (`?v=<hash>`), чтобы заменённое фото не оставалось в клиентском кэше. SwiftUI загружает их через `AsyncImage`: при загрузке виден индикатор, при ошибке или отсутствии URL — нейтральная заглушка `photo`. При старте настроен `URLCache.shared` на 32 МБ памяти и 128 МБ диска; Hosting отправляет `Cache-Control: public, max-age=3600`.

В ассетах приложения остаются только изображения интерфейса: `brandLogo`, `iconNext`, `iconCart`, `backgroundWallpaper`, а также иконка приложения. Исходники для повторной публикации фото находятся в `firebase/hosting/public/products` и не входят в iOS-приложение. Административный файл `firebase/seed/catalog.json` также не входит в приложение.

Hosting работает на бесплатном Spark без подключения Cloud Storage и биллинга. Фото доступны всем по прямой ссылке; правила Firestore продолжают ограничивать чтение каталога пользователями с подтверждённым email. Публиковать фото может только администратор через Firebase CLI; клиентское приложение файлов не записывает.

Для демонстрации используется тестовый аккаунт Firebase и учебные данные Firestore без реальных покупок и персональных данных. При недоступности Firestore приложение показывает ошибку и предлагает повторить загрузку; локального запасного каталога нет.

## Настройка Firebase

Проект Firebase — **OtusDiplomaWork** (`test-6d334`), тариф Spark. Android-приложение `com.alex.otus_shop` и его `google-services.json` относятся к тому же проекту, но iOS-приложение зарегистрировано отдельно с Bundle ID `com.alex.clothesshop`. Его настройки находятся в `ClothesShop/Resources/Documents/GoogleService-Info.plist`; Xcode включает файл в ресурсы приложения.

В Firebase Authentication включён вход по email и паролю. При регистрации аккаунт сначала создаётся в Firebase, затем пользователю отправляется письмо с подтверждением на русском языке. До перехода по ссылке приложение показывает экран ожидания: на нём можно повторно отправить письмо, обновить статус или выйти. После нажатия «Я подтвердил адрес» приложение обновляет пользователя и ID-токен. Неподтверждённый пользователь не попадает в каталог даже после повторного входа или перезапуска. Постоянные тестовые логин и пароль в репозитории не хранятся. При развёртывании Auth через Firebase CLI также создаётся служебное веб-приложение `Default Web App`.

Проверка сценария: зарегистрироваться с доступным email → открыть ссылку из письма → вернуться в приложение → нажать «Я подтвердил адрес». До последнего шага должен оставаться экран ожидания; после него откроется каталог. Для нового письма есть кнопка повторной отправки.

Cloud Firestore использует базу `(default)` в регионе `europe-west3`. Правила из `firestore.rules` разрешают чтение коллекций `categories`, `products`, `settings` и `notificationList` только пользователям с подтверждённым email. Общие данные нельзя менять из приложения; подтверждённый пользователь может читать и изменять только свою корзину `users/{uid}/cart`. Документ `settings/store` содержит `maximumCartItemQuantity`; это же значение проверяют серверные правила при записи корзины. В базе также находятся учебные документы `notificationList/welcome` и `notificationList/catalog`; каталог, настройки и дополнительные уведомления загружает скрипт (см. ниже).

### Избранные и профиль

Нижняя панель содержит «Товары», «Избранные» (сердечко) и «Профиль». Сердечки в каталоге, карточке товара и избранном используют одно состояние. Избранные товары сохраняются локально в UserDefaults с ключом по Firebase UID: они остаются после перезапуска и выхода, но не синхронизируются между устройствами. В пустом разделе показана подсказка.

В профиле отображается email из Firebase Auth. Формы «Смена пароля» и «Смена email» требуют текущий пароль для повторной авторизации. Новый пароль проверяется на длину от 6 символов и совпадение с повтором, а окончательные требования проверяет Firebase. Смена email отправляет подтверждение на новый адрес через `sendEmailVerification(beforeUpdatingEmail:)`; до перехода по ссылке действует старый адрес. После подтверждения обновите профиль кнопкой «Обновить профиль» — также он обновляется при открытии вкладки и возвращении приложения из фона. Кнопка «Выход из аккаунта» закреплена внизу над панелью вкладок.

Проверка: добавить товар сердечком → открыть избранное → открыть товар → убрать сердечко → вернуться к пустому списку. Добавить товар повторно, перезапустить приложение и проверить сохранение. В профиле проверить пустые поля, короткий пароль, несовпадение паролей и текущий email. С доступным тестовым аккаунтом проверить неверный текущий пароль, успешную смену пароля и подтверждение нового email; затем выйти и войти с обновлёнными данными.

На 06.10.2026 правила опубликованы, в Firestore создан `settings/store` с лимитом корзины 99, а также загружены 4 категории, 21 товар и 3 дополнительных уведомления. Всего в `notificationList` 5 документов.

Проект CLI задан в `.firebaserc`. Чтобы повторно опубликовать настройки после изменений, выполните `firebase deploy --only auth,firestore:rules --project test-6d334`. Для запуска в Xcode достаточно открыть проект и выбрать симулятор iPhone; конфигурационный plist уже добавлен.

### Загрузка демо-данных в Firestore

Скрипт `firebase/seed` загружает категории и товары из `firebase/seed/catalog.json`, уведомления из `firebase/seed/notifications.json` и настройки магазина из `firebase/seed/settings.json`. Коллекции `categories` и `products` приводятся в точное соответствие с файлом: лишние документы удаляются. Уведомления добавляются и обновляются, существующие `welcome` и `catalog` не трогаются. Для изменения лимита корзины отредактируйте `maximumCartItemQuantity` в `settings.json` и повторите seed либо измените то же поле в документе `settings/store` через Firebase Console.

1. Firebase Console → Project settings → Service accounts → **Generate new private key**. Сохранить файл как `firebase/seed/service-account.json` — он в `.gitignore`, коммитить его нельзя.
2. Установить Node.js 18+ и выполнить:
   ```
   cd firebase/seed
   npm install
   npm run seed:dry          # проверка файлов без записи
   GOOGLE_APPLICATION_CREDENTIALS=./service-account.json npm run seed
   ```
3. Опубликовать правила с новыми коллекциями: `firebase deploy --only firestore:rules --project test-6d334`.

Вместо сервисного ключа можно использовать существующий вход Firebase CLI:

```
firebase login
cd firebase/seed
npm install
npm run seed:dry
npm run seed:cli
```

`seed:cli` запускает тот же `npm run seed` с временными Application Default Credentials из сессии установленного Firebase CLI. Файл создаётся вне репозитория с правами `0600` и удаляется после выполнения. Этот вспомогательный режим использует внутренние модули CLI; проверен с Firebase CLI 15.31.0. Основной режим с сервисным ключом остаётся доступным.

Чтобы создать или изменить только `settings/store`, не синхронизируя каталог и уведомления:

```bash
npm --prefix firebase/seed run settings:dry
npm --prefix firebase/seed run settings:seed:cli
```

### Публикация фото товаров

Сопоставление старых imageset и id товара находится в `firebase/seed/prepare-images.mjs`. Первоначально скрипт копирует фото из ассетов; после миграции работает с `firebase/hosting/public/products`. Повторный запуск сохраняет пути и обновляет версии URL по содержимому файлов.

Из корня репозитория:

```
npm --prefix firebase/seed run images:prepare
npm --prefix firebase/seed run seed:dry
firebase deploy --only hosting --project test-6d334
npm --prefix firebase/seed run seed:cli
```

Для замены существующего фото отредактируйте файл `firebase/hosting/public/products/<product-id>.png` и повторите команды. Для нового товара добавьте файл и сопоставление в `prepare-images.mjs`, а товар — в `catalog.json`. Перед обновлением Firestore проверьте доступность опубликованного фото. Правила `storage.rules` для Hosting не нужны: это статические публичные файлы, а доступ к публикации регулируется правами Firebase проекта.
